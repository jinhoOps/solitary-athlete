## 오늘도 묵묵히, 잔디 한 칸.

혼자 운동해도 기록은 함께 쌓을 수 있습니다. `#오운완-인증`에 운동 메모나 사진을 남기면 묵묵이 기록을 모읍니다. 하루의 인증은 잔디 한 칸이 되고, Discord와 웹에서 지난 운동을 돌아봅니다.

순위를 매기기보다 자신의 리듬을 지키는 작은 운동 기록 공간을 만듭니다.

**현재는 설계·초기 설정 단계입니다.** 지침, 설계 문서, 브랜드 시안과 협업 템플릿을 준비했습니다. Discord 채널 4개와 묵묵 앱·봇 설치, 역할 연결, 아이콘·잔디 이모지를 구성했습니다. 공용 Supabase는 서울 리전 `github-jinhoOps`의 기존 `solitary_athlete` 스키마를 사용합니다. 아래 봇 기능과 웹보드는 구현·배포 예정입니다.

## 묵묵이 할 일

| 이용 방법 | 보여줄 내용 |
| --- | --- |
| `#오운완-인증`에 텍스트·사진 남기기 | 운동 기록 저장 후 ✅ 표시 |
| `/잔디` | 내 최근 28일 잔디와 최근 기록일 5개의 메모 |
| `/잔디 유저:@멤버` | 선택한 멤버의 잔디와 메모 |
| `#잔디-현황판` | 멤버들의 최근 28일 잔디를 같은 메시지에 갱신 |
| 웹 대시보드 | 최근 84일 잔디, 멤버 필터, 운동일 통계, 상세 메모 |

슬래시 결과는 채널 구성원에게 보이며 **표시 후 5분 뒤 삭제**하도록 설계합니다. 현황판과 운동 원본 기록은 계속 남습니다. 삭제는 예약 작업으로 처리하며 서비스 장애나 요청 지연 때는 늦어질 수 있습니다.

기록 날짜는 한국 시간(KST) 기준입니다. 같은 날 여러 번 인증해도 운동일은 1일로 셉니다. 인증 수집과 현황판 갱신은 매시간 실행할 예정이며, `/잔디`는 호출 시점에 **저장된 기록**을 조회합니다. 방금 작성한 인증이 수집되기 전에는 결과에 나타나지 않을 수 있습니다.

잔디는 **기록 없음 → 텍스트 인증 → 사진 포함 인증**의 세 단계입니다. 같은 날 사진 인증이 하나라도 있으면 한 단계 더 진한 녹색으로 표시합니다. 사진을 여러 장 남겨도 운동일은 하루 1일로 셉니다.

## Discord 공간

| 채널 | 역할 |
| --- | --- |
| `#공지-및-웹보드` | 이용 안내와 상세 웹보드 링크 |
| `#잔디-현황판` | 묵묵이 갱신하는 운동 현황 |
| `#오운완-인증` | 운동 메모·사진 인증 |
| `#운동-자유수다` | 일상 대화와 `/잔디` 조회 |

웹보드는 공개 페이지를 기본 설계로 합니다. 참여자의 표시명, 운동 날짜와 텍스트 메모가 공개되며, 사진 원본과 첨부 URL은 웹에 옮기지 않습니다. 이 범위는 참여 안내에 명시합니다.

[고독한 운동가 서버 열기](https://discord.com/channels/1559802401802952706/1559802402893340744) · 공지·현황판은 멤버 읽기 전용, 인증·자유수다는 쓰기 가능으로 설정했습니다. 설치한 묵묵에게 현황판 쓰기 역할을 연결했습니다. 실제 ID와 초기 설정 상태는 [DESIGN.md](DESIGN.md#17-discord-초기-설정-현황)에 기록합니다.

## 구현 예정 구성

| 구성 | 선택한 방향 |
| --- | --- |
| 인증 수집·현황판 갱신 | Python · uv · GitHub Actions |
| 기록 저장 | Supabase Postgres |
| 슬래시 응답 | Supabase Edge Functions · TypeScript |
| 5분 삭제 | 비공개 예약 큐 · Supabase Cron · 삭제 함수 |
| 상세 웹보드 | 바닐라 TypeScript · 정적 빌드 · GitHub Pages, 복잡해지면 React + TypeScript |

1. 서버·채널 설정과 DB 마이그레이션.
2. 중복 없는 인증 수집과 현황판 갱신.
3. `/잔디` 조회와 5분 삭제.
4. 정기 실행과 상세 웹보드 배포.

각 단계의 검증 기준은 [DESIGN.md](DESIGN.md#9-개발-단계와-완료-기준)에 있습니다. 구현을 시작한 뒤 실행법과 배포 주소를 추가합니다.
