# Discord 사진 지연 조회 구현 계획

> 실행자는 executing-plans 스킬로 아래 마일스톤을 순서대로 수행한다. 이 문서는 계획이며 구현·외부 배포는 후속 작업이다.

**목표:** 첫 화면에서 사진 다운로드 없이, 선택한 기록의 Discord 사진만 필요할 때 표시한다.

**구조:** 수집기는 첨부 메타데이터만 저장한다. 월간 코드로 보호된 Edge 함수가 원본 메시지에서 유효한 링크를 조회하고 브라우저가 Discord에서 이미지를 직접 받는다.

**기술:** Python/uv, 기존 solitary_athlete 스키마, Supabase Edge/Deno, 바닐라 TypeScript.

**기준:** [동작 설계](../../../ARCHITECTURE.md#2026-10-16-discord-사진-지연-조회-계획), [시각 설계](../../../DESIGN.md#후속-계획-discord-사진-미리보기).

## 공통 제약

- 이미지 파일의 별도 저장 없음. 첫 화면의 이미지 바이너리·사진 링크 갱신 요청 0건.
- 월간 코드 검증과 서버/채널 제한, 서버 전용 토큰. 익명 첨부 테이블 직접 읽기 금지.
- 조회 실패와 삭제를 구분하고 사진 표시 실패로 기존 운동 집계를 변경하지 않는다.
- 캐시 잔존과 서명 URL 공유 가능성을 안내하며 영구 보관을 보장하지 않는다.

## 1. Discord 미리보기 지원 확인

- [ ] 실제 이미지 첨부의 proxy_url 축소 요청이 원본보다 작은 파일을 반환하는지 크기·포맷·만료·모바일에서 확인한다. 비공개 이미지나 링크를 로그/문서에 남기지 않는다.
- [ ] 실패 시 사진 보기 버튼만 제공하는 경로를 확정한다. 원본 자동 다운로드로 우회하지 않는다.

- [ ] 메시지와 첨부 ID로 멱등 저장하고 필요한 최소 메타데이터만 보관한다. 기존 트랜잭션과 잔디 집계 계약을 유지한다.
- [ ] 과거 메타데이터 백필을 재실행 가능하게 구현하고 커서·메모 보존을 검증한다.
