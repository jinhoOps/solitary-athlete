# 지정 멤버의 인증 기록 수동 정리 구현 계획

> 실행자는 `executing-plans` 스킬로 마일스톤별 구현·검증·커밋·푸시한다. 현재 요청은 계획 작성이며 제품 코드·DB·서비스는 변경하지 않는다.

**목표:** `/기록정리 유저:@멤버`를 호출했을 때만 대상 멤버의 사라진 인증을 확인하고 잔디·메모·통계를 정리한다.

**구조:** 서명된 Discord 명령이 비공개 작업을 접수하고 기존 5분 수집기가 대상의 저장 메시지 ID를 제한된 양씩 확인한다. HTTP404/10008로 삭제가 확정된 원본만 취소하며 기존 날짜 재집계를 재사용한다.

**기술:** Python/uv·httpx·psycopg, Supabase Edge/Deno·기존 solitary_athlete 스키마와 응답 삭제 큐, 기존 TypeScript 웹 조회.

**설계:** [동작·데이터](../../../ARCHITECTURE.md#2026-10-16-인증-원본-삭제-반영-설계), [표시](../../../DESIGN.md#후속-계획-삭제한-운동-인증의-표시).

## 공통 제약

- 자동 전수 점검·최근 누락 후보 대조·과거 순환 점검을 추가하지 않는다. 수동 작업이 없으면 정리용 원본 조회0건.
- 유저는 필수. 기본 권한안은 MANAGE_GUILD 또는 ADMINISTRATOR. DM·다른 서버·봇 대상·일반 멤버 호출 거부.
- 사진 URL 만료·권한 오류·빈 목록은 삭제 증거가 아니다. 봇의 실효 권한 검증 + 원본 GET의 HTTP404/Discord10008만 삭제로 인정한다.
- 대상·채널·접수 시 메시지 상한을 고정한다. 다른 멤버나 새 인증을 정리하지 않는다.
- 기존 수집 잠금·KST 일수·일요일 주간 경계·300초 응답 삭제·맥북240초 전체 제한 유지.
- 작업당 한 실행 최대20개 메시지·30초, 429는 retry_after까지 보류, 일시 오류10회 연속이면 failed. 작업은 여러 실행에 나눠 완료한다.
- 메시지별 원본 변경·재집계·커서·건수를 한 트랜잭션으로 확정한다. 원문 메모·사진 URL·interaction token을 작업 큐에 저장하지 않는다.
- 새 상시 연결·Cron·DM/채널 완료 알림·새 웹 관리 화면을 추가하지 않는다.

## 검토할 실패 조건

권한이 사라져 빈 목록이 반환되는 경우, 403/10008과 404/10003, 동일 명령 재전송, 같은 멤버 중복 접수, 작업 중 새 인증, 여러 날/멤버 격리, 같은 날 마지막 사진/마지막 인증, DB 실패 후 중복 건수, 임대 만료 후 오래된 워커, 15분 넘는 작업, 절전 후 재개, 429·시간 예산·권한 회수 후 중단을 검증한다.

## 1. 삭제 확인과 비공개 작업 저장

대상: `mukmuk/discord.py`, `mukmuk/reconcile.py`(신규), `mukmuk/store.py`, 새 `supabase/migrations/*_mukmuk_reconcile_jobs.sql`, `scripts/test-db.sh`, `tests/python/test_reconcile.py`(신규), `tests/python/test_store.py`.

- [ ] 실패 테스트를 먼저 작성한다: 404/10008만 삭제, 코드 없는404·10003·403·429·5xx는 보존, 채널 권한 제거 시 정리0건.
- [ ] DiscordError에 안전한 오류 코드·retry_after를 추가하고 deadline 내 단일 조회를 지원한다. 기존 status 호출자와 호환한다.
- [ ] 봇/호출자의 관리·채널 권한을 역할·채널 덮어쓰기를 포함해 검사한다. 빈 목록에 의존하지 않는다.
- [ ] 서버 전용 workout_reconcile_jobs와 대상별 진행 중 작업 중복 방지 인덱스를 추가한다. interaction ID도 유일해야 한다. 앱 역할만 큐를 읽고 쓰게 한다.
- [ ] 접수 시 대상의 최대 저장 메시지 ID와 총 건수를 고정한다. 작업이 없거나 대상 기록이0건일 때 불필요한 Discord 원본 호출 없이 완료한다.
- [ ] 메시지 저장/삭제·날짜 재집계와 작업 커서/건수 갱신을 원자적으로 구현한다. DB 실패·중복 실행·임대 경합과 다른 사용자 보존을 실제 SQL로 검증한다.
- [ ] Python/DB 테스트 통과 후 커밋·푸시한다.

인터페이스: `verify_source(channel_id,message_id,deadline)` → present(message)/deleted/deferred(reason,retry_at). Store는 접수·동일 대상 작업 재사용·조회·선점·메시지별 원자 처리·재시도/완료를 제공한다. 작업 결과에 원문을 포함하지 않는다.

## 2. 관리자용 슬래시 명령·상태 조회

대상: `register_cmd.py`, `supabase/functions/_shared/interactions.ts`, `_shared/db.ts`, `_shared/reconcile.ts`(신규), `tests/edge/interactions.test.ts`, `tests/edge/reconcile.test.ts`(신규).

- [ ] 실패 테스트: 서명 오류, DM·다른 서버, 유저 누락·봇, 일반 멤버 호출, 중복 interaction, 진행 중 대상 재호출, 상태 조회만 하는 경우.
- [ ] `/잔디`를 유지하고 `/기록정리`를 추가 등록한다. 필수 USER 옵션 `유저`, 선택 BOOLEAN 옵션 `상태`(기본false), 관리 권한 기본값을 설정한다.
- [ ] 등록 권한에만 의존하지 않고 interaction 수신 시 실제 권한을 확인한다. 상태 조회도 동일 권한을 요구한다.
- [ ] 실행은 비공개 작업 접수 후 호출자에게만 응답한다. 상태True는 최신 작업 상태만 읽으며 새 접수를 하지 않는다. 응답은 기존 영속300초 삭제 큐로 관리한다.
- [ ] 접수 중 DB 실패 시 성공으로 알리지 않는다. 장시간 작업 token을 정리 큐 밖에 보관하거나 나중에 DM/공개 채널로 보내지 않는다.
- [ ] 기존 `/잔디` 본인/타인·서명·5분 삭제 테스트와 신규 Edge 타입 검사 통과 후 커밋·푸시한다.

## 3. 기존 수집기에서 접수된 작업만 실행

대상: `mukmuk/reconcile.py`, `mukmuk/sync.py`, `tests/python/test_collector.py`, `tests/python/test_reconcile.py`.

- [ ] 작업 없음→추가 원본GET0건, 다른 멤버 격리, 상한 이후 신규 인증 보존,20개/30초 제한, 절전/재시작·429·연속 오류10회·권한 회수·DB/현황판 실패 테스트를 먼저 작성한다.
- [ ] 기존 잠금 아래 정상 신규/수정 수집 → 준비된 작업 한 개 선점 → 제한된 대상 원본 확인 → 최신 집계로 현황판 갱신 순서로 연결한다.
- [ ] 저장된 대상 ID만 조회한다. 접수 후 확인된 HTTP200의 수정은 기존 정규화 경로로 반영하고 삭제는 확정 조건을 다시 검사한다.
- [ ] 작업 cursor는 성공 처리 뒤에만 이동한다. 미확인 위치는 재시도하며 연속 일시 오류10회면 부분 완료 건수와 함께 failed로 종료한다. 작업 간 최근 처리 시각으로 공정성을 유지한다.
- [ ] 접수 작업이 남아도 한 번의 실행에서 반복 루프로 모두 비우지 않는다. 로컬/Actions 중복 실행·이전 임대의 결과 반영을 차단한다.
- [ ] 작업 실패로 신규 인증을 롤백하거나 기존 수집 커서를 이동하지 않는다. 로그는 건수·상태·안전한 오류 코드만 남긴다.
- [ ] Python/DB 회귀 통과 후 커밋·푸시한다.
