# 계정 연결 구현 완료 검토

2026-10-22 · 작업 브랜치 `jinhoOps/mukmuk-account-link`. [구현 계획](../plans/2026-10-21-account-link.md)의 9개 작업을 구현했다. 운영 DB·Discord·Pages·설치 런타임에는 아직 적용하지 않았다. 새 기능은 기본 비활성 상태다.

## 검증

- Python 94건, Vitest 85건, Deno DB 7건, Chromium 107건 통과.
- TypeScript 타입 검사, 공개 테스트 설정의 정적 빌드·산출물 검사, 5개 Edge entrypoint의 `deno check`, `git diff --check` 통과.
- 새 PostgreSQL17.11 클러스터에서 마이그레이션을 처음부터 적용하고 Python·Deno 통합 검사를 통과했다. 수집 연결 2개와 동시 Edge SQL의 연결 제한 3, 중복 전달·세션 만료, 원본 보존·과거 관측·적용 롤백을 검사했다.
- 실제 pooler의 연결 반환과 Discord 명령·버튼·모달·Gateway 운영 동작은 배포 전 확인 대상으로 남는다.

## 최종 독립 검토

중요 결함 2건을 실패하는 회귀 테스트로 재현한 뒤 한 차례 보완했고 전체 검사를 다시 통과했다.

1. 상대 계정의 탈퇴·자격 상실이 취소·이력 조회를 막던 문제: 호출자 권한과 상대방 적격성 검사를 분리했다. 승인 검사에서 확정된 자격 상실은 결과와 함께 무효화하고, 5xx·불완전한 200은 보류한다.
2. 연결·해제를 구분할 수 없던 승인 화면: 동작 종류, 양쪽 동의 시각, 해제의 추가 동의 예외, 거절 사유를 표시한다.

경미한 후속 문서 정리 1건: 설계 명세 §7의 사람 집계 최초 `calculation_version=1` 설명이 구현과 다르다. 실제 구현·마이그레이션·ARCHITECTURE의 기준은 기존 관측 1, 사람 투영 2다. 이 문구의 정리는 후속으로 남겼다.

## 구현 중 판단과 한계

- Docker daemon이 응답하지 않아 후반 DB 검증을 별도 소유 로컬 PostgreSQL17.11로 진행했다. CI의 PostgreSQL17 Docker 경로는 유지한다. 차이가 있다면 CI에서 확인해야 한다.
- 파일 소유권 검사를 `local_owner.py`로 분리해 launchd 선검사가 Gateway를 import하지 않게 했다. 공유 세션과 트랜잭션 잠금 경계가 늘어난 만큼 연결 누수·롤백 경합을 통합 검사했다.
- 기존 SQL API를 유지하는 지연 생성 facade는 각 SQL 범위를 직렬 처리한다. 느린 SQL이 뒤 요청을 지연시킬 수 있어 DB timeout을 두며, 계정 온라인·전달·결과 확인은 호출 기한을 전달하는 별도 짧은 범위를 쓴다.
- 실제 Supavisor·Discord 검증은 이 구현 범위 밖이므로 신규 기능을 비활성 상태로 남겼다. 활성화 전 운영 검증 없이는 실환경 오류를 배제할 수 없다.
- 독립 검토자는 전체 테스트를 재실행하지 않고 소스와 테스트 및 두 재현을 검토했다. 작성자가 전체 검사를 실행·확인했으며, 푸시한 동일 소스의 CI를 추가 확인한다.
